# 海外仓运营监控系统 MVP 交付计划

> **面向 Agent 执行者：** 必须使用子技能 `subagent-driven-development`（推荐）或 `executing-plans` 按任务逐项推进本计划。任务跟踪使用复选框语法 `- [ ]`。

**目标：** 基于已定稿的 PRD，交付一版可测试、可上线，面向单个仓库运营主管团队使用的海外仓运营监控系统 MVP。

**架构：** 本次交付拆分为五条工作流：数据接入、监控计算、提醒触达、前端页面，以及 QA/UAT 与上线准备。关键路径为：数据映射 -> 计算服务 -> 首页/明细页 -> 提醒集成 -> 联合测试/UAT。

**技术栈：** 现有业务系统数据源、监控服务、按小时调度的同步任务、Web 前端监控看板、企业消息/邮件集成、QA 测试用例、UAT 检查清单。

---

## 交付假设

- 推荐团队配置：1 名后端工程师、1 名前端工程师、1 名 QA、1 名产品经理、1 名仓库业务负责人。
- 交付范围：仅支持单仓，仅支持小时级刷新，不包含处理闭环工作流。
- 数据源假设：业务系统可通过 API 或数据库同步方式提供或暴露出库订单、入库单、箱级、SKU 上架以及 ETA 数据。
- 提醒渠道假设：至少有一个可用于集成的外部渠道，例如企业微信或邮件。
- 推荐排期：5 周，包含 UAT 和上线缓冲时间。

## 建议模块结构

实现应拆分为以下逻辑模块。下方路径是建议研发团队采用的实现落点。

- `backend/src/integrations/business-system/`
  职责：拉取源数据、字段标准化、增量同步。
- `backend/src/monitoring/calculators/`
  职责：出库超时计算、到仓不齐计算、上架超时计算、未来 7 天到仓预估计算。
- `backend/src/monitoring/repositories/`
  职责：标准化实体持久化、风险结果查询、首页聚合查询。
- `backend/src/alerts/`
  职责：首次预警、超时汇总重发、消息模板。
- `backend/src/config/`
  职责：预警提前量、严重阈值、接收人配置。
- `frontend/src/pages/dashboard/`
  职责：首页顶部状态、今日总览、异常清单、未来 7 天预估。
- `frontend/src/pages/anomalies/outbound/`
  职责：出库异常明细页。
- `frontend/src/pages/anomalies/inbound/`
  职责：到仓不齐明细页。
- `frontend/src/pages/anomalies/shelving/`
  职责：上架异常明细页。
- `frontend/src/pages/settings/alerts/`
  职责：轻量配置页。
- `qa/testcases/warehouse-monitoring/`
  职责：规则验证、UI 测试、提醒验证、UAT 脚本。

## 工作流概览

1. 数据源与字段映射
2. 监控规则计算
3. 首页与明细页开发
4. 提醒集成与配置
5. QA、UAT 与上线准备

## 压缩版本：4 周

仅当以下三个条件同时满足时，才建议压缩到 4 周交付：

- 业务系统字段映射已经稳定
- 提醒通道权限已经审批完成
- 前后端可以从第 2 周开始并行推进

压缩版安排：

- 第 1 周：任务 1 + 任务 2 启动
- 第 2 周：任务 2 完成 + 任务 3 + 任务 4 启动
- 第 3 周：任务 4 + 任务 5 + 任务 6
- 第 4 周：任务 7 + UAT + 上线准备

风险提示：
- 如果字段映射或消息集成晚 2 天以上，压缩版计划大概率无法按时落地

## 关键路径

1. 字段映射签字确认
2. 增量同步与标准化存储
3. 监控规则计算输出
4. 首页与明细页集成
5. 提醒触达集成
6. UAT 与上线准备

步骤 1 至步骤 3 上的任何延期，都会直接拖延整个项目。

## 推荐团队配置

- 后端工程师：负责同步、计算、提醒调度和配置后端
- 前端工程师：负责首页、三类明细页和配置页
- QA：负责规则用例、UI 用例、提醒用例和 UAT 检查清单
- 产品经理：负责需求冻结、范围控制与 UAT 验收
- 仓库业务负责人：负责字段确认、业务规则确认与 UAT 参与

## 主要风险与应对措施

### 风险 1：业务系统字段质量不稳定

应对措施：
- 在任何大规模前端开发开始前先完成任务 1
- 将数据异常列表与业务异常列表严格分离

### 风险 2：外部消息权限开通滞后

应对措施：
- 若企业微信审批较慢，保留邮件作为兜底通道
- 最迟在第 4 周前完成提醒集成

### 风险 3：预估所需源字段不完整

应对措施：
- 允许按比例估算剩余重量与体积
- 在测试阶段内部标记预估结果的可信度等级

### 风险 4：范围膨胀到处理闭环或报表能力

应对措施：
- 严格执行 PRD 第 3.3 节与第 12 节的 MVP 边界
- 在 MVP 阶段拒绝新增工作流型需求，除非它替换已有范围

## 上线门槛

只有满足以下全部条件，团队才应进入正式上线：

- 数据映射与时区规则已签字确认
- 首页与三类明细页全部可用
- 至少一个外部提醒通道已验证通过
- 数据延迟场景可在 UI 中清晰感知
- 仓库运营主管已完成 UAT
- 回滚负责人和上线负责人已明确

## 建议沟通节奏

- 每周一次项目例会：产品、前端、后端、QA 参加
- 第 2 周到第 4 周每周两次阻塞项评审
- 第 5 周开始时召开 UAT 评审会
- 第 5 周结束前召开上线评审会
