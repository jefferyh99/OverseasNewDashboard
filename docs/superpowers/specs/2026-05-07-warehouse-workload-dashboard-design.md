# 海外仓监控系统调整设计

- 日期：2026-05-07
- 阶段：方案设计
- 状态：待评审

## 1. 背景

现有系统最初定位为海外仓运营异常监控 MVP，首页核心围绕异常风险展示，重点关注：

- 出库异常
- 到仓不齐
- 上架异常

经过与业务进一步沟通，系统定位需要调整为“双看板”模式：

- 一条线看仓库当天与次日的工作量
- 一条线看即将超时与已超时的风险

本次调整不取消现有异常能力，而是在保留异常看板的前提下，新增一个以仓库作业量为中心的工作量看板，并将其作为默认首页。

## 2. 本次设计范围

本次仅讨论产品与页面设计，不涉及业务代码实现细节。

本次设计范围包括：

- 默认首页切换为工作量看板
- 保留并重新定位现有首页为异常看板
- 工作量看板的信息结构、模块命名与跳转关系
- 工作量看板中“未来7天待到仓货量预估”模块的下钻设计
- 三个下沉详情页设计
  - 出库包裹详情页
  - SKU 详情页
  - 箱子详情页
  - 待到仓货量详情页

本次 MVP 范围仓库：

- `DE`：德国仓
- `ON`：安大略仓

## 3. 产品定位调整

### 3.1 工作量看板

工作量看板定位为仓库主管的默认首页，用于回答以下问题：

- 当前仓库今天还有多少活要处理
- 明天预计会有多少到仓工作量
- 当前还有多少已超时但未处理完成的积压任务

### 3.2 异常看板

异常看板继续保留，但定位收敛为风险监控视角，用于回答以下问题：

- 哪些对象即将超时
- 哪些对象已经超时
- 三类异常分别有哪些风险明细

### 3.3 两个看板的边界

工作量看板强调：

- 工作量总览
- 今日执行
- 明日压力
- 已超时待处理积压

异常看板强调：

- 即将超时
- 已超时
- 风险明细与异常处理入口

因此：

- 工作量看板中的“已超时待处理任务”只展示已超时且当前仍未处理完成的汇总数
- 异常看板展示即将超时与已超时两类异常对象

## 4. 导航与全局规则

### 4.1 默认首页

系统默认进入 `工作量看板`。

### 4.2 一级导航

MVP 阶段建议至少保留以下入口：

- 工作量看板
- 异常看板

现有异常明细页继续存在，作为二级下钻页面使用。

### 4.3 仓库切换

两个看板共享同一个仓库切换条件。

- 支持 `DE / ON`
- 当前仓库切换后，看板与下钻页都围绕该仓库展示

## 5. 工作量看板设计

## 5.1 模块顺序

工作量看板首页按以下顺序展示：

1. 已超时待处理任务
2. 今天待处理任务
3. 明天待处理任务
4. 未来7天待到仓货量预估

该顺序对应仓库主管的实际查看习惯：

- 先看积压风险
- 再看今天作业
- 最后看明天压力
- 最后补充未来工作日货量趋势判断

## 5.2 已超时待处理任务

### 5.2.1 模块定位

该模块只展示“已经超时且当前仍未处理完成”的对象汇总，不展示明细表格。

### 5.2.2 展示维度

- 包裹出库异常
- 入库单箱子到仓不齐
- SKU 上架异常

### 5.2.3 交互

点击某个卡片后，跳转到对应异常页面，并自动带入：

- 当前仓库
- `overdue`

### 5.2.4 与异常看板差异

该模块只看“已超时待处理”；
异常看板看“即将超时 + 已超时”。

## 5.3 今天待处理任务

该模块包含 3 个部分：

- 今天待出库包裹
- 今天待到仓箱子
- 今天待上架 SKU

### 5.3.1 统一展示命名

页面统一使用：

- 已处理
- 待处理

但各对象底层含义不同：

- 出库：已处理 = 已出库；待处理 = 未出库
- 到仓：已处理 = 已到仓；待处理 = 未到仓
- 上架：已处理 = 已上架；待处理 = 未上架

### 5.3.2 今天待出库包裹

展示字段：

- 总包裹量
- 已处理
- 待处理

交互：

- 提供“查看全部”
- 跳转到 `出库包裹详情页`
- 默认带入 `当前仓库 + 今天`

### 5.3.3 今天待到仓箱子

展示字段分两层：

第一层为总览：

- 总箱数
- 总重量
- 总体积
- 总件数
- 总 SKU 数

以上指标需体现已处理 / 待处理口径。

第二层按货运方式展开：

- 海运
- 空运
- 快递
- 卡派

每种货运方式下展示：

- 箱数
- 重量
- 体积
- 件数
- SKU 数

每个指标单元格内展示：

- 已处理
- 待处理

交互：

- 提供“查看全部”
- 跳转到 `箱子详情页`
- 默认带入 `当前仓库 + 今天`

### 5.3.4 今天待上架 SKU

展示字段：

- 总 SKU 数
- 已处理
- 待处理

交互：

- 提供“查看全部”
- 跳转到 `SKU 详情页`
- 默认带入 `当前仓库 + 今天`

## 5.4 明天待处理任务

### 5.4.1 模块定位

MVP 当前模块名保留为“明天待处理任务”，但本次仅承载“明天待到仓箱子”。

### 5.4.2 明天待到仓箱子

统计口径：

- 按预计到仓日期统计
- 只看尚未完全到仓的货

展示字段：

- 总箱数
- 总重量
- 总体积
- 总件数
- 总 SKU 数

同样按货运方式展开：

- 海运
- 空运
- 快递
- 卡派

与今天待到仓箱子不同的是：

- 首页模块内不展示已处理 / 待处理
- 仅展示明天计划工作量

交互：

- 提供“查看全部”
- 跳转到 `箱子详情页`
- 默认带入 `当前仓库 + 明天`

## 5.5 未来7天待到仓货量预估

### 5.5.1 模块定位

该模块用于给仓库主管提供未来 7 个工作日的到仓货量趋势判断，辅助做提前排班与容量安排。

### 5.5.2 展示形式

首页使用柱状图展示未来 7 个工作日的趋势。

- X 轴：未来 7 个工作日日期
- Y 轴：总箱数

鼠标移动到柱子上时，展示：

- 总箱数
- 总重量(kg)
- 总体积(m3)
- 海运柜数
- 卡派板数

### 5.5.3 交互

- 模块右侧提供“查看全部”
- 点击后跳转到 `待到仓货量详情页`
- 默认带入 `当前仓库 + 未来7天`

## 6. 下沉详情页统一设计原则

## 6.1 通用能力

三个下沉页统一采用同构设计，均支持：

- 查询
- 导出

本次 MVP 不设计页面内处理动作。

## 6.2 通用页面结构

每个详情页统一包含：

1. 标题区
2. 筛选区
3. 统计条
4. 明细列表

## 6.3 通用查询规则

从首页进入时默认带入首页条件，但允许用户在详情页调整查询条件。

## 6.4 通用列表范围

三个页面默认均展示“全部对象”，而不是只展示待处理对象。

原因：

- 首页卡片展示的是总量、已处理、待处理
- 详情页需要能完整解释这三个数字

状态切换通过筛选器完成。

## 6.5 通用导出规则

导出遵循当前页面筛选条件。

即导出结果与当前页面所见一致，包括：

- 当前仓库
- 当前时间条件
- 当前状态条件
- 当前关键词条件

## 6.6 未来7天待到仓货量预估下钻

工作量看板中的“未来7天待到仓货量预估”模块，右侧需增加“查看全部”链接。

点击后跳转到 `待到仓货量详情页`。

该页面与“明天待到仓箱子”模块数据结构相似，但时间范围更长，并增加筛选能力。

## 7.3 筛选项

## 7.4 统计条

## 9. 箱子详情页

## 10. 待到仓货量详情页

## 10.1 页面定位

该页用于承接工作量看板中“未来7天待到仓货量预估”模块的“查看全部”入口。

页面目标是把首页的未来货量预估展开为可筛选、可导出的明细视图。

## 10.2 默认条件

从首页进入时默认带入：

- 仓库：当前仓库
- 时间范围：未来7天

## 10.3 页面结构

建议同样采用轻量同构结构：

1. 标题区
2. 筛选区
3. 统计条
4. 明细列表

## 10.4 筛选项

根据当前业务要求，MVP 先保留：

- 仓库
- 时间范围
- 货运方式
- 查询
- 重置
- 导出

## 10.5 统计条

建议展示：

- 总箱数
- 总重量(kg)
- 总体积(m3)
- 海运柜数
- 卡派板数

## 10.6 列表粒度

建议一行展示一个“到货日期 × 货运方式”的汇总行。

该粒度与“明天待到仓箱子”模块类似，但多了跨多天查询的能力，因此需要增加：

- 到货日期

## 10.7 列表字段

- 到货日期
- 货运方式
- 总箱数
- 总重量(kg)
- 总体积(m3)
- 总件数
- 总SKU数
- 卡派板数
- 海运柜数

显示规则：

- `卡派板数` 仅当货运方式为 `卡派` 时有值，其他货运方式显示 `-`
- `海运柜数` 仅当货运方式为 `海运` 时有值，其他货运方式显示 `-`

## 10.8 与箱子详情页的区别

箱子详情页关注的是：

- 一行一个箱子
- 到仓作业对象明细

待到仓货量详情页关注的是：

- 一行一个到货日期 × 货运方式
- 未来货量汇总
- 供主管做未来几天人力安排参考

## 11. 三个详情页与异常页的关系

三个详情页都属于工作量执行页，目标是解释“总量、已处理、待处理”。

因此它们应：

- 默认看全部
- 支持筛选
- 支持导出

它们不承担以下职责：

- 强调即将超时
- 强调已超时
- 承接异常处理主入口

这些职责继续由异常看板和异常明细页承担。

待到仓货量详情页则属于计划分析页，目标是解释未来货量压力。

## 12. MVP 不纳入范围

本次设计明确不纳入：

- 页面内处理动作
- 页面内备注、分配、人工确认
- 复杂批量操作
- 额外新增“明天待出库”“明天待上架”模块
- 多仓总览首页

## 13. 当前假设与待后续实现确认项

以下内容已形成设计假设，但后续实现前仍需与业务数据字段映射确认：

- “今天待出库包裹”的时间口径到底使用下单时间、承诺出库时间还是业务定义任务日期
- “今天待上架 SKU”的时间口径到底使用到仓日期、上架任务日期还是业务定义任务日期
- “今天/明天待到仓箱子”的状态计算字段与业务系统字段映射
- “未来7天待到仓货量预估”与“待到仓货量详情页”的汇总口径是否完全一致
- 导出文件字段顺序与字段中文名

这些问题不影响当前页面结构设计，但会影响实现时的数据口径与接口字段定义。

## 14. 结论

本次调整方案的核心结论如下：

- 系统从单一异常首页升级为“工作量看板 + 异常看板”双看板模式
- 工作量看板为默认首页，MVP 支持 `DE / ON` 两仓切换
- 工作量看板按“已超时待处理任务 -> 今天待处理任务 -> 明天待处理任务”的顺序展示
- 工作量看板额外补充“未来7天待到仓货量预估”趋势模块
- 现有异常能力保留，但聚焦风险监控
- 新增四个下沉页，其中 3 个工作量执行页 + 1 个未来货量分析页

该方案适合作为本轮 MVP 的设计定稿基础。
