页面边界
  • 不做通用规则引擎，只做统一模板下的仓库参数配置。
  • 不把 8:00-17:00 常规工作时间放进规则字段，因为它不参与实际判定。
  • 节假日先走手工维护，不接外部节假日服务。
字段解释提示区
  • 截单时间：决定订单是否顺延到下一个工作日。
  • 超时时点：决定订单何时进入已超时。
  • 预警提前量：由超时时点向前倒推，决定何时进入即将超时。
  • 时区：统一做仓库当地时间换算，并自动处理夏冬令时。

页面 B

规则计算预览区

配置页右下或独立 Tab 可以放一个“规则预览”模块，让业务在改完参数后立刻看到系统怎么判断。这样能减少“字段配了但不知道实际效果”的沟通成本。

目的：配置即验证

规则流转线框

统一算法，不按仓库改代码，只换参数
1. 转仓库当地时间 订单创建时间 当前时间 已出库时间
→
2. 判断是否工作日 周末命中？ 节假日命中？
→
3. 判断截单前后 夏令时用 15:00 冬令时用 16:00
4. 得到承诺日 当天 或下一个工作日
→
5. 拼接超时时点 承诺日 + 18:00 得出 overdueAt
→
6. 倒推预警时间 overdueAt - 60 分钟 得出 warningAt

试算样例表

改参数后立即重算
场景 下单时间 是否工作日 承诺日 超时时点 结果
工作日截单前 周二 14:20 是 周二 周二 18:00 当天完成
工作日截单后 周二 16:30 是 周三 周三 18:00 顺延
周五截单后 周五 16:30 是 周一 周一 18:00 跨周末
法定节假日下单 假日 11:00 否 下个工作日 下个工作日 18:00 跳过假期
边界口径提示
  • 下单时间等于截单时间，仍按当天处理。
  • 周末和法定节假日下单，不参与当天截单比较。
  • 已出库订单不进入风险状态。
  • 即将超时来自提前量，不写死 17:00。
页面 C

德国仓确认样例卡片

这块更像给业务评审用的“确认卡”，把德国仓的关键口径直接翻译成可读样例，避免只盯字段名导致误解。

用于评审，不一定进入正式页面

样例 1：夏令时截单前

下单：德国当地周二 14:20

截单：15:00

已超时：周二 18:00

样例 2：周五截单后

下单：德国当地周五 16:30

已过夏令时截单 15:00

周六周日跳过

已超时：周一 18:00

样例 3：法定节假日下单

下单：德国法定节假日 11:00

当天不比较截单时间

顺延：下一个工作日

即将超时：工作日 17:00

已超时：工作日 18:00
